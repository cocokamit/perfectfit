04 · Idea → production

How I ship a client feature

01Scope

Pin down “done”

Turn the client's request into acceptance criteria before writing a line. If “done” is unclear, I ask. One question now saves three revisions later.

02Plan

Plan with the AI, decide as the human

Use Claude Code's plan mode plus a project CLAUDE.md with conventions. I review the plan like a PR: schema, edge cases, what not to build.

03Build

Small diffs, fast loops

Front-end, API, and data layer in thin vertical slices. Each slice runs end-to-end before the next one starts. No 2,000-line surprise commits.

04Review

Read every line

AI writes the first draft; I own the final one. I check for security holes, N+1 queries, and invented APIs. Claude is great. Claude is also confident.

05Test

Prove it, don't claim it

Tests on the logic that matters, a real run of the app, and the unhappy paths: empty states, bad input, slow network.

06Ship

Deploy + tell people

CI, preview URLs, a clear changelog for the client, and a README so the next developer (or future me) isn't lost.

07Iterate

Feedback → fix → repeat

Client says “can it also…?” Same loop, same day where possible. My favorite sentence is “that's already deployed.”

07 · FAQ

Questions you might have.

Did AI build this website?

With me, yes, and that's the point. Claude Code wrote much of the first draft. I set the direction, reviewed every line, cut what was fragile, and made the calls. That's the job you described, done in the open.

Isn't a 3D blob a bit much?

For a job application? Probably. For client work, I default to simple and boring. The blob is a one-off. It knows. It's fine with it.

How fast can you ship?

Fast enough that clients see progress within days, not weeks. Not so fast that “working demo” gets mistaken for “production-ready.”

What happens when Claude is wrong?

I catch it in review or in tests, fix it, and if it's a pattern, I add a rule to the project's CLAUDE.md so it doesn't happen again. Mistakes become guardrails.

Why is the cursor doing that?

Those lines are attention weights: it “attends” to whatever is clickable nearby, like a tiny transformer. Leave it idle and it waits for a prompt. Click and it commits.
